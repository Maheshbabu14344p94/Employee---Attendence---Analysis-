# REVIEW.md

| # | Where | What is wrong | How to notice | Fix |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Uses the input datetime's timezone/offset as if it were the shift timezone and uses truncation around a grace boundary incorrectly for some offsets. | Pass a UTC instant for a 09:30 IST shift and compare 09:40:00 with 09:40:01. | Convert the instant to IST, truncate to seconds, anchor to the correct shift start (including overnight shifts), and apply the strict `> 600 seconds` grace rule. |
| 2 | `compute_work_hours` | Python's built-in `round` uses ties-to-even, not the required half-up rounding. | Use a duration whose hour value lands exactly on a half-cent boundary. | Use `Decimal` with `ROUND_HALF_UP` for the two-decimal result. |
| 3 | `compute_overtime` | Builds an end time on the same date, so overnight shifts are wrong; it also lacks the 30-minute minimum. | Punch out at 06:20 for a 22:00–06:00 shift: expected 20 minutes overtime, not an end time on the wrong date. | Derive the correct shift bounds from punch-in and count whole minutes only when at least 30. |
| 4 | `create_employee` | A preflight duplicate check would be race-prone and shift start/end equality is accepted. | Submit simultaneous creates with the same code, or identical shift times. | Enforce uniqueness with a MongoDB unique index and map duplicate-key errors to 409; validate different shift times. |
| 5 | `list_employees` | `skip` is `page * page_size`, skipping the first page, and `total` ignores the department filter. Results are not sorted. | Request page 1 with page size 2 and filter by department. | Use `(page - 1) * page_size`, count the filtered query, sort by `emp_code`, and cap page size at 100. |
| 6 | `punch_in` | Unknown employees cause a server error; seconds/local time are used instead of validated epoch milliseconds; check-then-insert races; date handling ignores overnight shifts. | Punch for an unknown code, send a seconds timestamp, or issue concurrent duplicate requests. | Validate timestamp input, return 404 for unknown employees, use IST/overnight rules, and rely on a unique `(emp_code,date)` index for race safety. |
| 7 | `list_attendance` | Loads all matching records into Python before pagination, which is too slow for 100k records; response pagination and index usage are not suitable. | Seed a large collection and request a small page. | Count and page in MongoDB with a stable indexed sort, validate date ranges, and cap page size. |
| 8 | Starter API | Punch-out, regularization, analytics, and explain endpoints are missing. | Request any endpoint marked “You” in the contract. | Implement the remaining endpoints, derived-field rules, audit history, aggregation pipelines, and executionStats explain output. |

**Examined and retained:** the natural key `(emp_code, date)` is appropriate because the contract explicitly forbids exposing MongoDB `_id`; status values are constrained to the five contract values. All analytics are implemented as MongoDB aggregation pipelines rather than fetching logs and aggregating in Python.
